# 认证浏览器协议

仅在公开路线不足、私有配置启用了认证浏览，而且用户明确授权本次读取时使用。

## 会话选择

1. 先只读列出已连接 profile 和相关顶层窗口，不要为了“检查登录”创建新页面。
2. 多 profile 时，每次调用都显式指定 profile；不得修改全局默认 profile。
3. 用户指出某个现有页面已登录时，只在确有必要时绑定该页面。通用浏览器表面和站点适配器表面可能完全隔离，名称相同也不证明它们共享登录态。
4. 公共站点、创作者后台、SSO 子域和移动预览页是不同 auth surface。`whoami` 或另一个子域成功不能证明目标页面已登录。

## 失败分类

- 新页面返回 `AUTH_REQUIRED`，但用户已有登录页面：标记 `browser_session_mismatch`，停止创建页面。
- 登录标记存在于不同子域或产品表面：标记 `auth_surface_mismatch`。
- 浏览器桥未连接：标记 `browser_bridge_unavailable`；这不授权修复扩展、切换 profile 或重用其他登录态。
- 二维码、验证码、账号挑战或重新登录：停止并交还用户。

不要仅凭适配器失败宣称用户“已退出登录”。应在目标 auth surface 直接验证用户请求的只读动作和必要的可见账号标记。

## 所有权与清理

操作前记录现有窗口/页面句柄。只关闭当前工作流创建且被桥明确标记为工具所有的页面；借用的用户页面只能解除绑定。所有权不确定时保留页面并报告。

解除绑定后，不要为了确认解绑而继续对已解绑会话执行 `state`、`tab list` 或页面命令，因为这可能重新创建空白页面。运行时、扩展或适配器升级后，必须重新验证成功和失败两条路径都不会遗留窗口；当前 Skill 不自动升级它们。

Playwright 或其他浏览器自动化只能使用独立临时 profile，绝不能连接、复制或读取认证会话所有者的 profile。
