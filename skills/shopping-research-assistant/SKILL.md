# 商品选购助手

从“该花多少钱”推进到“具体买哪一件”。结论必须能追溯到当前商品、具体变体、商铺、评论和来源。本 Skill 是通用商品选购流程，不是某个品类的固定模板，也不是无人监督的下单代理。

执行前读取 [安全与权限](references/security-and-permissions.md)。默认只读、无登录态、无购物车变更、无长期偏好保存；这三类能力分别需要用户明确授权，互不自动继承。

## 权限边界

- 默认只检索、读取、比较公开信息并提出建议。访问登录后页面必须得到当前任务的明确授权，并复用用户已经配置好的官方客户端或专用会话；不得代用户登录、索取凭据、导出 Cookie 或访问无关账户页面。
- 搜索和读取登录后页面不授权购物车变更。选择变体、调整数量或加入购物车前，必须再次列明商品、规格、数量和平台，并取得当前任务对这些准确对象的明确授权。授权不扩展到其他商品或下一次任务。
- 不得绕过验证码或账号挑战，也不得领取优惠、联系商家、提交订单、付款、点赞、收藏或发表评价。删除购物车条目、清空购物车或改变其他已有条目也不属于购买前自动化授权。
- 用户已要求自动化时，助手负责完成所有可安全执行的普通步骤，不得把页面查找、规格选择、加购或读价重新交给用户。若出现验证码、滑块、短信验证、设备确认、人脸认证或账号异常提示，只让用户完成该安全检查；用户确认完成后，从最近的已验证状态自动续跑，不要求用户重复普通操作。
- 不调用付费 API、返佣、邀请或推广接口；移除链接中的跟踪参数。
- 长期记录默认关闭。启用时必须由用户明确选择仓库外状态目录；不得写入 Skill 目录、共享 Skills 目录或代码仓库。账号、完整地址、订单号、收礼人身份等非必要敏感信息不得写入长期记录。
- 标价、会员价、券后价、预估到手价和分期价必须分开。只有商品身份、变体、售后条件均可比时才能声称更便宜。
- 保留用户原始用途，不把普通购买改写成营销、品牌或转化率项目。

## 执行顺序

1. 锁定用途、预算弹性、地区、时效、硬条件和可接受风险。礼物、儿童、食品、健康或安全相关商品提高审核等级。
2. 选择通用品类模块；礼物是叠加场景。读取 [品类与场景模块](references/category-modules.md)，只加载适用部分。未知品类使用通用内核，不得硬套相近门类。只有用户已经明确启用长期记录并配置仓库外状态目录时，才运行 `python scripts/shopping_memory.py context --category <category> --state-root <private-state-root>`；未启用时跳过，不创建状态目录。偏好冲突时向用户确认；历史经验只用于规划本次搜索。
3. 建立来源地图并广泛检索，目标覆盖两个独立交易平台、独立体验、投诉或消费者权益和品牌官方来源。记录实际覆盖及缺口；不足会限制高置信度结论，不自动淘汰商品。
4. 识别当前在售具体单品和关键变体，再审核商品评论、投诉、商铺和售后。静态接口失败不等于评论不可读；按 [评论访问与差评读取](references/review-access.md) 继续正常页面路径。最终候选的所有可访问负面正文必须逐条阅读。
5. 先比较各价格带的实际缺陷、投诉严重度和售后增益，再决定合理预算；星级、销量和付款人数不能证明质量。
6. 按 [证据与硬门控](references/evidence-and-evaluation.md) 分别判断商品与证据。`FAIL` 表示发现不合格，`BLOCKED` 表示未核实。高置信度发布门与条件推荐资格分别计算；受限时满足条件推荐要求仍可给主选、备选和置信度。
7. 输出结论前可运行 `python scripts/shopping_memory.py validate --input <record.json>` 做离线校验。只有用户明确启用长期记录时，才按 [长期沉淀协议](references/persistence.md) 写入指定状态目录；未启用时不保存偏好、商品记录或调研历史。写入失败必须报告，不能静默跳过。

## 工具路由

- 使用 `web-tool-router` 检索公开网页。除淘宝/天猫外，评论静态接口、桌面页或移动页不可读时，不能立刻判定全部评论受阻；继续使用独立临时浏览器，通过页面可见的“差评”“追评”“问答”和分页控件读取。淘宝/天猫按下一条直接进入官方客户端。
- 淘宝与天猫的商品、评价、价格和店铺查验默认直接使用已经登录的淘宝官方桌面客户端；读取前先看 [淘宝与天猫官方客户端查验](references/taobao-tmall-official-client.md)。不要自动启动、恢复或重试 `taobao-login` 专属浏览器，也不要默认调用 `opencli taobao`；只有用户在当前任务中明确要求这一例外时才可使用。客户端暂时无法被安全控制时，准确记录 `CLIENT_CONTROL_UNAVAILABLE`，继续外部来源，不得偷偷绕回专属浏览器。
- 用户明确要求自动化购买前流程时，优先使用平台正常页面、官方客户端能力或受限的 `diannao-kongzhi` 完成导航和读取。任何加购、变体或数量状态改变都必须满足本 Skill 的逐对象确认要求，并用商品 ID、规格文字或购物车目标条目验证。不得使用坐标点击、按键注入或其他更宽权限工具补洞。
- 京东在匿名页面仍受限、且当前任务已获用户明确授权时，可用 OpenCLI 读取已经配置好的 `jd-login` 专用会话。使用前读取 [OpenCLI 京东评论读取器](references/opencli-review-reader.md)。只有明确的差评筛选、分页证据和适配器版本才能进入评论覆盖记录；成功空数组本身不是“零差评”证据。
- 普通网页会话、官方客户端和自动化专用会话必须分别记录。某个自动化会话返回身份限制，只能证明该会话受限，不能外推为用户账号、普通浏览器、官方客户端或整个平台受限。
- 登录已失效、出现验证码、滑块、短信验证、设备确认或账号挑战时，暂停该路径并等待用户正常完成，不得绕过；用户确认完成后自动续跑。只有验证仍未完成、用户不处理或会话继续不可用时，才记录 `BLOCKED` 和缺失范围。不得为了调查主动修改账号、浏览器或平台设置。
- 调查由助手负责，不得把差评、追评、负面问答、店铺售后截图列成用户必须完成的资料作业。受限后继续允许访问的独立来源；同类风控不循环重试。只有用户特有的信息（如预算或结算金额）才需要用户补充，不索要完整地址或账号凭据。
- 大量评论需要归纳时可使用 `analyzing-user-feedback`，但逐条阅读、计数和来源记录仍由本流程负责。
- 搜索摘要、榜单、聚合页和营销文章只能提供线索；关键事实必须回到可读原页或独立第二来源。

## 门控状态

每道门只允许：

- `PASS`：证据满足要求，可以继续。
- `FAIL`：发现明确问题，候选淘汰或结论不成立。
- `BLOCKED`：证据缺失、页面受限或工作未完成，不得形成确定结论。
- `N/A`：确实不适用，并写明理由。

`publication` 只表示高置信度发布资格，不是所有商品的购买合格证。`recommendation.mode` 区分 `strong`、`conditional`、`none`，程序另返回 `conditional_eligible` 和不符合原因。保留每项已核实的事实，不把一个缺口扩展成所有项目失败。使用 `scripts/shopping_memory.py` 校验；不得仅写“条件推荐”来绕过实质要求。

## 交付要求

结果通常包含：

1. 有具体依据的预算和价格比较，以及更贵是否真实降低关键风险；不为凑三个价格带编造价格或商品。
2. 少量具体候选的身份、变体、平台、店铺、价格类型、链接和核验日期。
3. 评论访问路径、页面宣称量、可展开量、已读量、主要投诉原意、刷评或软广信号、商铺风险及门控状态。
4. 有依据的主选和备选；发布门受限但 `conditional_eligible=true` 时标为“条件主选/备选”。实质硬条件或关键安全证据缺失时只列待核实候选；没有合适备选就直说。
5. 仍会随账号、地区或时间变化的下单前核对项。
6. 若用户启用了长期记录，提供沉淀回执：状态目录、原始记录、偏好事件、可信经验和未晋升原因；未启用时明确写“长期记录未启用，未保存购物画像”。

允许提供稳定公开商品图，但不得伪造图片。旧经验只用于确定搜索方向，不能替代本次价格、库存、配送、店铺和商品状态的实时核验。

续接本次类型的任务或修复记录时，读取 [受限调研与证据纠错经验](references/research-lessons.md)。这些经验是流程规则，不是任何品牌的质量背书。

本 Skill 仅显式调用；不要把它变成每次出现商品、礼物、预算或价格时自动介入的通用流程。
